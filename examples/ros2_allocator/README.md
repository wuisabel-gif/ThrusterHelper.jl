# thruster_allocator (ROS 2 node)

A drop-in ROS 2 node that turns a desired wrench into per-thruster commands,
using a header generated by [ThrusterHelper.jl](../../)'s `export_cpp()`. The
allocation is a precomputed matrix-vector multiply baked into the header, so at
runtime the node has no dependency on Julia or ThrusterHelper: O(N), no heap, no
iteration.

## Topic interface

| dir | topic | type | notes |
|-----|-------|------|-------|
| sub | `cmd_wrench` | `geometry_msgs/msg/Wrench` | `force.{x,y,z}` and `torque.{x,y,z}` become `[Fx, Fy, Fz, tau_x, tau_y, tau_z]` |
| pub | `thruster_commands` | `std_msgs/msg/Float64MultiArray` | ordered to match `kActuatorNames` in the header |

Both topics are parameters (`input_topic`, `output_topic`), so remap them to your
stack.

## Build

This is a normal ament_cmake package. Drop it into a colcon workspace `src/` and:

```sh
colcon build --packages-select thruster_allocator
source install/setup.bash
ros2 run thruster_allocator allocator_node
```

Then, from another terminal:

```sh
ros2 topic pub /cmd_wrench geometry_msgs/msg/Wrench \
  '{force: {x: 30.0, y: 8.0, z: -5.0}, torque: {x: 0.0, y: 0.0, z: 4.0}}'
ros2 topic echo /thruster_commands
```

## Use your own vehicle

`include/thruster_allocation.hpp` ships pre-generated for the default
`bluerov_vehicle()` (BlueROV2 Heavy, 8 thrusters). To target your layout, edit
the `vehicle` in [`generate_header.jl`](generate_header.jl) and regenerate:

```sh
julia --project=/path/to/ThrusterHelper.jl generate_header.jl
colcon build --packages-select thruster_allocator
```

The header carries the actuator count, names and per-thruster limits, so the node
adapts with no C++ changes.

## Verify without ROS 2

[`test/smoke.cpp`](test/smoke.cpp) checks the generated `allocate()` against the
Julia reference, no ROS install needed:

```sh
cd test
g++ -std=c++17 -I ../include smoke.cpp -o smoke && ./smoke
# OK: allocate() matches Julia reference
```

If you regenerate the header for a different vehicle, update the expected values
in `smoke.cpp` from your own `allocate(...)` output.

## Notes and limits

- Only `:minimum_norm` and `:weighted` allocation export to a constant matrix;
  `:qp` / `:minimum_power` are iterative and have no baked-in form.
- With `saturate=true` (the default) the node applies a direction-preserving
  scale to each thruster's `max_thrust`, so a saturating wrench is scaled down
  rather than clipped per-thruster. Regenerate with `saturate=false` for raw
  least-squares commands.
- This package is a starting point, not colcon-tested in this repo's CI (which
  has no ROS 2). The allocation math is verified by `test/smoke.cpp`; the ROS 2
  glue is deliberately minimal so it is easy to audit and adapt.
